# تشغيل ورقي حقيقي — أربعة عشر يوماً

هذا الدليل لتشغيل النظام على **جهازك**، ببيانات سوق حقيقية، مدّة
أسبوعين متصلين. لا يمكن تنفيذه في بيئة تطوير مؤقّتة بشبكة محجوبة.

---

## لماذا لا يمكن اختصارها

النظام يتّخذ قراراً واحداً لكل شمعة **مُغلَقة**، ويرفض البيانات البائتة
عبر `INSUFFICIENT_DATA_QUALITY`. هذان قيدان صحيحان يمنعان معاً ضغط
أسبوعين في ساعة: أي إزاحة للمحور الزمني تجعل الشموع تتكرّر فيُلغيها
حارس التكرار (`ALREADY_PROCESSED`).

أربعة عشر يوماً من القرارات تحتاج أربعة عشر يوماً من الشموع. النقطة
الوحيدة التي تُختصر هي **الباكتست**، وهو شيء آخر: يجيب «ماذا كان
سيحدث تاريخياً»، لا «هل يصمد النظام حيّاً».

## ما يلزم

| | |
|---|---|
| جهاز يعمل بلا انقطاع | حاسوب شخصي، أو VPS رخيص |
| بايثون | 3.11 أو أحدث |
| شبكة | وصول إلى `api.binance.com` (قراءة عامة فقط) |
| مفاتيح | **لا يلزم شيء** — الوضع الورقي لا يلمس حساباً |
| مساحة | أقل من 100 ميغابايت للأسبوعين |

الوضع الورقي يقرأ أسعاراً عامة ويُنفِّذ على وسيط محاكى محلياً. لا أمر
يصل بينانس، ولا رصيد حقيقي يُلمَس.

## الإقلاع

```bash
unzip CRYPTO_TRADING_V11_FIXED.zip && cd crypto_trading_v11
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 -m unittest discover -s tests     # تأكّد أن كل شيء سليم أولاً
python3 live_trader.py check              # فحص البيئات
```

ثم شغّل. `watchdog.py` يُعيد التشغيل تلقائياً عند أي انهيار — وهو
المطلوب لأسبوعين:

```bash
# Linux/macOS — يستمر بعد إغلاق الطرفية
nohup python3 watchdog.py paper > paper_14d.log 2>&1 &
echo $! > paper.pid
```

لمسح الأصول الأربعة بدل رمز واحد:

```bash
SCAN_SYMBOLS=BTCUSDT,ETHUSDT,BNBUSDT,SOLUSDT \
  nohup python3 watchdog.py paper > paper_14d.log 2>&1 &
```

**لا توقفه ولا تُعد تشغيله يدوياً بلا سبب.** جزء من قيمة الأسبوعين هو
إثبات أن الحالة تنجو من التقطّعات الطبيعية وحدها.


أو اللوحة:

```bash
cd dashboard && pip install -r requirements.txt && ./run.sh
```

### ما يستحق التوقّف عنده فوراً

| المؤشر | المعنى |
|---|---|
| `KILL_SWITCH` مُفعَّل | النظام أوقف نفسه — اقرأ السبب قبل أي شيء |
| أحداث `CRITICAL` متكرّرة | خلل حقيقي، لا ضجيج |
| `UNRESOLVED_INTENTS` | نية عالقة تمنع التداول — تحتاج فحصاً |
| صفر صفقات بعد أسبوع | ليس بالضرورة عطلاً — راجع أسباب الرفض في تبويب أفضل فرصة |

## عند انتهاء الأسبوعين

```bash
python3 live_trader.py report --env paper --json > paper_14d_report.json
python3 live_trader.py gate   --env paper
```

`gate` يقول إن كان التشغيل يستوفي شروط الترقية إلى Testnet.

### كيف تقرأ النتيجة بأمانة

أسبوعان بفريم 4 ساعات = **84 شمعة**، وعدد الصفقات سيكون على الأرجح
بين صفر وعشر. هذا حجم عيّنة **لا يُثبت ولا ينفي حافّة** — لا إحصائياً
ولا تقريباً.

ما يُثبته الأسبوعان فعلاً:

- أن النظام يعمل متصلاً بلا انهيار ولا تسريب حالة.
- أن الأوامر لا تتكرّر، وأن الحالة تُستعاد بعد الانقطاع.
- أن الأرقام المُسجَّلة تطابق ما حدث فعلاً.
- أن سلوك «لا تداول» معقول لا شلل دائم.

وما لا يُثبته: **الربحية**. من يقرأ ربحاً في 84 شمعة يقرأ ضوضاء.

## بعدها

1. **Testnet** — نفس الشيء بمفاتيح `testnet.binance.vision`، وعندها
   يُختبَر `ExchangeAccountProvider` مقابل رصيد حقيقي لأول مرّة
   (حالته الآن `NOT VERIFIED`).
2. **مدّة أطول** — أشهر لا أسابيع، إن أردت الاقتراب من دلالة إحصائية.
3. **Mainnet** — مقفول في المصدر، ولا يُفتَح بنجاح تشغيل ورقي وحده.

## تحذير أخير

سلامة التنفيذ ليست ربحية الاستراتيجية. كل العمل الهندسي في هذا المشروع
يضمن أن الأمر لا يتكرّر وأن الحالة تُستعاد وأن الأرقام صادقة — **ولا
يقول شيئاً عن الربح**. حالة الحافّة في هذا المشروع `UNKNOWN`، ولن
يغيّرها أسبوعان.

## الحل

### 1. المعرّف الحتمي

```python
build_client_order_id('ENTRY', 'BTCUSDT', recommendation_id=42)
# → 'en-BTCUSDT-r42-v1'   ثابت دائماً
```

نفس النية ⇒ نفس المعرّف عبر إعادة التشغيل والعمليات. إعادة المحاولة
تحمل المعرّف ذاته، فترفضه بينانس بـ `-2010 Duplicate order sent`.

`version` يُرفع **فقط** حين تكون إعادة المحاولة مقصودة — كإعادة وضع
وقف بعد التأكد من زوال السابق.

### 2. آلة حالة النية

```
RESERVED ──send()──> IN_FLIGHT ──ok──────> CONFIRMED
    │                    ├──rejected────>  REJECTED
    │                    └──timeout─────>  UNKNOWN ──recover()──> CONFIRMED/FAILED
    └──abort()──────────────────────────>  ABORTED
```

**النية تُحفَظ في القاعدة قبل أي نداء شبكة.** لو انهار البرنامج بين
الحفظ والرد، تبقى `IN_FLIGHT`، ويحسمها الإقلاع التالي.

### 3. التعافي بالاستعلام لا بالتخمين

```python
client.order_by_client_id(symbol, cid)   # GET /api/v3/order?origClientOrderId=
```

عند الانقطاع نسأل بينانس عن نيّتنا **بالاسم**:
- موجود ومنفَّذ ⇒ `CONFIRMED`، نسجّله ولا نعيد الشراء
- `-2013 Order does not exist` ⇒ لم يصل قطعاً، آمن
- الاستعلام نفسه فشل ⇒ `UNKNOWN` ⇒ **مفتاح إيقاف**، لا تخمين

### 4. تصنيف الأخطاء

| النوع | الحالة | السلوك |
|---|---|---|
| `-2010`, `-1013`, `-2015`, `-1021`… | `REJECTED` | نهائي، لم يُنشأ |
| مهلة، انقطاع، 5xx | `UNKNOWN` | **يجب** الاستعلام |

الافتراض بأن المهلة تعني الفشل هو أصل المشكلة كلها.

### 5. قفل العملية

قفل في القاعدة بنبض. عامل ثانٍ يرفض الإقلاع. القفل الميت (نبض
أقدم من 180 ثانية) يُنتزع تلقائياً. فقدان النبض أثناء التشغيل يوقف البوت.

### 6. قيود القاعدة

```sql
order_intents.client_order_id  UNIQUE   -- يحسم السباق
orders.client_order_id         UNIQUE
positions.recommendation_id    UNIQUE   -- مركز واحد لكل توصية
```

`INSERT OR IGNORE` يُرجع 0 للخاسر — سباق العمليات محسوم في القاعدة.

## التحقق

```
128 اختباراً — OK
  102  V4+V5
   26  منع التكرار
```

سيناريوهات مغطاة:

| السيناريو | النتيجة |
|---|---|
| مهلة **بعد** التنفيذ | يُسترجَع، أمر واحد |
| إعادة محاولة بعد مهلة | `DuplicateOrderError`، صفر نداءات شبكة |
| مهلة بلا تنفيذ | `FAILED`، لا أمر |
| رفض صريح | `REJECTED` نهائي |
| إعادة تشغيل بنية عالقة | تُحسم قبل أي تداول |
| **6 عمّال متوازين** | **أمر واحد على المنصة** |
| معاملات مختلفة بنفس المعرّف | مرفوض — ارفع version |
| بيع مكرر | محجوب |

## ما لم يتغيّر

منطق الاستراتيجية، الإشارات، المؤشرات، حساب المخاطر، والمقاييس —
**لم يُمَس أي منها**. 102 اختباراً من V4/V5 ما زالت تنجح بلا تعديل.
هذا العمل يخص سلامة التنفيذ فقط، ولا يحسّن أي نتيجة.

## قيد باقٍ

`order_by_client_id` يعمل على أمر واحد. بينانس يحتفظ بالأوامر المنتهية
لفترة محدودة — نية عالقة لأيام قد لا تُحسم. عندها تبقى `UNKNOWN`
ويُفعَّل مفتاح الإيقاف، ويلزم فحص يدوي. هذا مقصود: التوقف أأمن من التخمين.
